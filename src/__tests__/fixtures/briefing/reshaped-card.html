1. should a background ticker rewrite the Slack progress card every 90 seconds?
premise 2 hours old
what
The card freezes for ten to seventeen minutes at a time today, because nothing updates it on a clock. A ticker would rewrite it every 90 seconds from what the worker is already doing. No model runs in that loop, so it cannot change the answer.
how the ticker works, and what it costs
The ticker reads the worker's own progress file and rewrites one collapsed line, "Investigating: how many criticals are left, 6m". Expanded, the row shows the steps done so far and the step running now. It writes through the same outbound door every other card uses, so the schema still refuses a wall. The cost is one more resident writer per turn and one more thing that can fail while the turn is otherwise fine. The alternative that needs no new process is a rewrite on each tool result, which is cheaper to build and jumps around rather than ticking.
why you
You are the only person who reads these cards while the work is running.
options
A: add the ticker on a 90 second clock. B: rewrite the card on each tool result instead. C: leave the card frozen and say so in it.
