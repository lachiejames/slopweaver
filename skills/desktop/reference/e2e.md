# Proving a desktop change on the real app — `desktop e2e`

Everything in the desktop app that can be end to end tested is, so it never regresses and the owner always works
with a fully functional app. A desktop or console change is proven by walking a real bundle, not by its unit tests
alone.

```bash
slopweaver desktop e2e                                   # the installed app
slopweaver desktop e2e --app <dir>/mac-arm64/Slopweaver.app   # a candidate, before `desktop install`
slopweaver desktop e2e --only queue,queue-card,voice     # a subset, in walk order
slopweaver desktop e2e --only pages                      # just a published page in the viewer
slopweaver desktop e2e --app <candidate> --call --only call-live   # the call leg's pilot: one real call
slopweaver desktop e2e --app <candidate> --call --call-hold-minutes 5   # the walk, then every call scenario
slopweaver desktop e2e --call --call-card <kind>:<id> --only card-read   # one real call reading a named card
slopweaver desktop e2e --call --call-card all --only card-read,card-read-typed   # every open card, voice and typed
```

## Never while the owner is on a call

An e2e run once interrupted the owner's call, so e2e is refused only while the owner is on a call. Before anything launches the verb reads every console's voice call
leases and asks AVFoundation whether another app holds a microphone (`src/desktop/onCallHold.ts`); either HOLDS the
run, exit 4, naming the rule, and a failed read holds too, exit 1. Both are re-read before every launch and walk
step, in each scenario's preflight and at every Talk press, so a call the owner picks up mid-run stops it there and no test
call is placed beside one. No hatch. A headset reading in use while it only plays audio over-refuses, on purpose.

## What it walks

The Queue, its first card, the voice in its pinned tab ([`queue-pinned`](e2e-queue-pinned.md)), the voice window's reading of that Queue (`queue-screen-reading`: through the real `requestVoiceQueue` bridge, its `action_items` must be the head of the pinned tab's `data-card-key` order, read before and after the ask; pure half `src/desktop/e2eQueueScreen.ts`),
the + tab menu ([`new-tab`](e2e-new-tab.md)), every other sidebar page by its OWN link (a broken link fails), Settings and Presence,
the voice window's chat box and call button, the docs, a published page. No page is reached only by its address.

The `pages` step publishes the walk's OWN inert page through the real publisher, opens it in the viewer, and takes it
back out of the store and its folders afterwards: [the fixture page](e2e-page-fixture.md).

The voice step also checks what the voice page tells main its controls are, because main's cursor watch takes the
owner's clicks over every box it reports: rows scrolled up out of the messenger's history were reported where they sit
in layout, a column up to the top of the owner's screen, and Chrome's extension icons under it stopped answering.
It draws a fixture clear of the widget — a clipped scroller of rows scrolled to its end, past the preload's 32-box cap,
and a control with a child over its shoulder — reads the report the built preload sent main, and fails
`CONTROLS_UNCLIPPED` when a box covers the clipped-away rows, `CONTROLS_UNDRAWN` when one misses what is drawn
(`src/desktop/e2eControls.ts`). It judges only a report sent after the fixture went in, off a page that held still
across it; `CONTROLS_UNREPORTED` means no such report came, not that one was wrong. The fixture is removed before the
photograph.

The `orb-drag` step drags the voice's orb the way a person would: to the work area's top
left, held, let go, then back past the bottom-right corner. Every move goes into the instance's page, never the Mac's
cursor. It fails `ORB_DRAG_BROKEN` naming each thing a person would see: a median frame over 34ms or one over 150ms, the widget
changing size mid-drag, the window re-fitting more than once, any part besides the orb drawn while held, a jump on
release, or an orb dragged back that rests anywhere but its old place with the default kept (`src/desktop/e2eOrbDrag.ts`).
Its held and let-go photographs are the main process's capture, because a page screenshot taken mid-drag came out blank.

The list is `e2eSteps()` in `src/desktop/e2ePlan.ts`, built from the console perf walk's `CONSOLE_ROUTES`, so a new page joins both walks at once.

Each step waits for its landmark and for every loading mark to clear (the perf walk's own definitions), up to 30s,
then photographs the page. It fails, most serious first, on: a blocked action, an uncaught page error, a
`console.error`, a 5xx answer, Next's error overlay, a missing landmark, or a page still loading at the cap
(`src/desktop/e2eOutcome.ts`); [reading a `still-loading` verdict](e2e-still-loading.md). Photographs and `report.json` land in
`$SLOPWEAVER_HOME/proof/desktop-e2e/<started instant>/`, or `--out`. A step whose page draws a staleness mark also writes
`<photograph>.stale-marks.json`: each mark's hover words read off the page, naming which readings did not answer.

**An empty Queue is a state, not a failure.** The card step then reads **not applicable**, printed `N/A`, counted
apart from `passed` and `failed`, and never a pass: [the empty Queue](e2e-empty-queue.md).

## Why it is safe to run beside the owner's app, off a call

- **A test instance, never the owner's copy.** The bundle is launched by `playwright-core`'s Electron launcher with
  `--slopweaver-desktop-e2e=<throwaway dir>` (`desktop/src/e2eMode.ts`). It has its own saved state and its own
  single-instance lock, and does none of the shell's automatic acts: no menu bar icon unless [`--menu-bar`](e2e-menu-bar.md), no fleet launch into cmux,
  no update check, no console started, no permissions guide. The owner's running app is never quit, focused or changed.
- **The walk looks, never presses.** A card is opened and photographed, never answered; the chat box is found, never
  typed into; no call is placed unless `--call` asks (below). A step that pressed an option would send something as
  the owner. A page still does on load what it does when the owner opens it: Pull requests with a stale reading runs its landing sync, a GitHub READ recorded
  in the local readings ledger. Nothing a load runs reaches another person.
- **Playwright drives the page, not the Mac's cursor.** Clicks are dispatched into the page, so the walk does not
  move the owner's mouse, and the owner's mouse does not spoil the walk. The instance's windows do appear on screen while it runs.
- **It reads the console the checkout already serves.** If the Queue never shows within 90s it photographs what did
  and stops with `CONSOLE_NEVER_SHOWN`; check `slopweaver checkout console`. `--checkout <worktree>` walks a
  worktree's own console (`scripts/docs-site.sh --start`), which proves a `site/` change before it lands; that one is
  a DEV server, slower on a first read ([still-loading](e2e-still-loading.md)). A worktree with a stale built CLI is
  refused before launch (`STALE_BUILT_CLI`, `src/builtCli/servingCheckout.ts`): run `slopweaver dev build` there.
- **`--context work|slopweaver` picks the instance's work context**, as the console's switcher does, after every
  launch (the walk, the card inventory, each call and each relaunch), so a count is read off the Queue that holds the
  cards. The owner's app keeps its own context. Unset, the instance starts in the console's own default. If the address,
  the stored choice or the Queue's drawn context chip does not read back as asked, the walk stops with
  `CONTEXT_NOT_CHOSEN` and a call's launch fails.
- **`--settle-cap <seconds>` moves only how long a walk step waits to settle** (default 30, at most 600); what a
  longer one measures is in [still-loading](e2e-still-loading.md).
- **A build from before protocol 2 is refused** (`UNSUPPORTED_BUILD`). One from before the switch would ignore it and
  start as a full second copy of the owner's app. A protocol-1 build would record its calls as the owner's words. The bundle declares
  the protocol with `SlopweaverDesktopE2EProtocol` `2` in its `Info.plist`.

## Building a candidate to walk

`desktop install` builds and installs in one go, so a change is walked BEFORE install by building into a folder:
`yarn --cwd desktop install --immutable`, then `yarn --cwd desktop app --config.directories.output=<dir>`. The
bundle lands at `<dir>/mac-arm64/Slopweaver.app`, unsigned. Walk it, then install from main once the change has
landed. Remove the folder afterwards: LaunchServices registers every bundle it sees, and the install unregisters
stale copies by identifier.

## The call leg — `--call`

`--call` adds REAL voice calls after the walk, each on a fresh visible test instance whose microphone is a WAV
`/usr/bin/say` rendered (Chromium's `--use-file-for-fake-audio-capture`, looped, with `AudioServiceSandbox` off on
that instance only: sandboxed, the audio service cannot open the file and the call hears silence), over a quiet room's noise, never digital zero (`ROOM_RMS`, why on it). A call spends on the owned plans and writes a real transcript into the owner's talk store.
That transcript is MARKED, because the owner's console serves the call and the server's origin alone would read it as the owner's.
The test instance's windows carry `--slopweaver-instance=e2e` (`desktop/src/desktopBridge.ts`), the preload exposes
whatever value that argument has as `window.slopweaverDesktop.instance`, and the page reads ANY marker present as the
test instance's, its bridge kept or refused (`site/lib/desktopShell.ts` `instanceMarkOf`), so a malformed one is never dropped into the owner's words; it
sends `instance: "e2e"` with every transcript batch, retries included. The route passes `talk transcript
--console-instance e2e` beside the server-derived origin flags, never in place of them, and the verb stamps
`origin.instance: "e2e"` on the open line (`src/talk/callOrigin.ts`). A marked origin is never the owner's: `talk unread` sets
it aside as `NOT THEIRS` (`the desktop e2e test instance, through …`), and continuity, the chat thread and card landing
pass the call over — once ANY open line of a call is marked, a later unmarked open does not make what follows the
owner's (`src/talk/callOpened.ts`, `callOrigin.ts`'s `originAfterOpen`), so nor does it wake the chair. A renderer crash's
closing batch carries the marker too (`site/lib/overlayCrashRecovery.ts`). It appends to the owner's live home only through the owner's own console: the route wakes no chair, no
card lands from it automatically, and `talk land` refuses a `call:` anchor into it (`TEST_INSTANCE_CALL`). On any other console the marker is judged as that
console. A relay from the instance is refused (403) before anything runs, and `talk relay` takes no such flag.
Every prompt but `call-live`'s still says it is an automated end to end test; `call-live`'s mic says only "Hello.", the
way the owner opens a call, because announcing a test would hide the greeting under test. The fleet may start calls and click the owner's desktop freely. The leg runs on
the owner's console only: `--checkout` naming anything but a main checkout the owner's profile declares, with `--call`, is refused before launch (`CALL_CONSOLE_NOT_HIS`), because
`talk transcript` refuses a console that is not the owner's writing the live talk store and the call could never be proven
ended. A candidate bundle reads the console it is pointed at, so the leg proves the shell against the owner's console.

**Safety, in code rather than prose.** The leg holds the `desktop-e2e-call` operation lock; before each scenario it
reads the on-call hold, then every console's call leases AND the call registry (`GET /api/talk/held`) of the target and
of every checkout the owner declares, whether or not git confirms it this instant. A live lease holds the run AT ONCE (`CALL_ALREADY_LIVE`, exit 4), never waited out:
the previous scenario proved its own leases gone, so a live one is a call it did not place. A held voice call, or a typed
conversation not yet at rest (ten quiet minutes, a chosen bound, `TYPED_AT_REST_MS`), is waited out, then refused
(`CONVERSATION_HELD`). One at rest it runs beside, untouched and a stranger to it, saying so on a `PREFLIGHT` line, bar
before a scenario that types into the messenger (`besideAtRestFor`, `src/desktop/heldConversations.ts`). An unreachable
registry is waited on, then refused; no recorded server holds nothing. Last it reads every call in the shared call store, whatever its file's modified time, so a call held in
ANOTHER console whose lease lapsed is seen too: any call this leg did not place, another leg's included, never ended and
heard from in the last five minutes is waited out (`CALL_STILL_OPEN`, `src/desktop/unendedCalls.ts`), and the hold is
read once more (`src/cli/commands/desktop/e2eCallLegPlan.ts`). The reads are snapshots, not a lock the owner's calls take,
so a call the owner opens in another console after the last read is not PREVENTED; it is DETECTED: after every scenario the
whole on-call hold and the call store are read again, and a live lease, the real microphone in use, or a call the leg
did not place that was open while it ran stops the leg (`ON_CALL`/`CALL_OVERLAPPED`). The
microphone is also what catches a call of the owner's whose console stopped writing, which the store's five-minute quiet
window reads as abandoned. Two residuals, stated: a call the owner opens AND ends inside one scenario, its transcript still
queued, since nothing on disk records it yet; and a call whose console stopped beating, writing AND holding the
microphone for five minutes, which nothing on this machine tells from a dropped one. The console refuses the test instance's offer
beside anything but a typed conversation at rest too, ending nothing (`e2e-voice`, `site/lib/talkArbiter.ts`); every Talk press waits for zero live leases.
A crashed page may place a call with no press, so the whole hold is read before every renderer crash, allowing one live
lease per test call the scenario has placed (a crashed call's lease outlives it by up to a minute): one more live
lease, a torn one or a microphone in use holds the leg. Every typed send reads the same whole
hold, allowing none, and records it exactly as a Talk press does. After each scenario it hangs up, closes, and waits
until every plan call it opened has an end line in the console log, every transcript an end, and no lease is live. It then checks that every transcript
it tracked, and every one that appeared in the store while it ran (the store cannot say who wrote one, so a call of
the owner's placed mid-scenario stops the leg here as the lease check would), carries the test instance's marker on each open
line. A scenario that cannot prove all of that STOPS the leg (`STOPPED` line, `report.json`'s `fatal`). Evidence is correlated by call id, never by time: the plan
lines in the serving console's `<record>.log`, the shell's `~/Library/Logs/Slopweaver/desktop-events.jsonl` (shared
with the owner's app), the call store. Each scenario's `call` member in `report.json` carries its plan and transcript ids,
lease ids, heap samples and verdict, and the log lines it read.

**A fold is not a drop.** A click into another app while no call is up folds the card to the orb, and the fold
outlives the press into the call, so mute is hidden while the call talks on. Each live, connecting and hang-up read
first presses the orb whose label carries a call's headline (`FOLDED_CALL`, `e2eCallPage.ts`), the press the owner
would make. Measured with the owner at their Mac: three "dropped" verdicts whose transcripts show the call answering.

**After a crash the page is driven another way.** Playwright's page for a crashed renderer stays crashed while
Electron reloads the same window, so the recovered page is read, pressed and photographed from the main process
(`webContents.executeJavaScript` as a user gesture, `capturePage`), in `e2eCallView.ts`. A press there is a DOM
`click()`, and a page error the reloaded renderer throws is not heard. The long task's session details tray hides
the transcript while open, so it is closed once the work goes quiet and the answer read after.

**Known limit.** A lease that appears mid-scenario is attributed to the scenario; a call the owner places in that window is
caught only as more plan calls opened than the scenario could open (`overlapping-calls`). The heap bound is provisional (`src/desktop/e2eHeapTrend.ts` names the re-measure).

**What it does not walk**: tray ([drawn with `--menu-bar`](e2e-menu-bar.md), never clicked), fleet launch and an update's install, switched off in a test instance by design; unit-tested in `desktop/src/`. An update's swap is `update-swap-resume`.
