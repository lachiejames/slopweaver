# The standing sweep contract — the file the wakeup READS, not a paragraph you retype

This is the STANDING half of the sweep, and the only copy of it. `slopweaver supervisor sweep-prompt` renders
the prompt you arm; it names THIS FILE by path and carries only the shift state. Read it every tick, in order.

**Why it is a file.** MEASURED over eleven handoffs: 412–998 of every armed prompt's 592–1,240
words were standing procedure retyped by hand; one rule ran to eight wordings, then vanished while still true.

## Arm it like this

```bash
slopweaver supervisor sweep-prompt --budget                        # the word budget past which a shift overflows
slopweaver supervisor sweep-prompt --shift "<this tick's state>"   # or --shift-file <path>, or --shift-file -
```

Pass the render's output verbatim as `ScheduleWakeup`'s `prompt`. An over-budget shift renders within the 700-word
cap as a head plus `[… N more words — the whole shift state is <path>; …]`: **woken on that pointer, read the file**.
It refuses, together, a shift naming a standing step below and one naming a **command-line option** — which flags
a verb takes is standing procedure, held here, in [derived-narrative.md](derived-narrative.md) and
[verbs.md](verbs.md). Numbers and measurements: [sweep-cycle.md](sweep-cycle.md) § Arm it.

## The order, every tick

**On your FIRST tick only, before step 1: confirm you INVOKED the skill rather than read it.** `slopweaver cmux events --name agent.hook.PreToolUse --workspace <your ws>` prints the tool per call, so a `Skill` line for this workspace is the witness — no line means it was never invoked, so invoke it now (SKILL.md's own first section, and [briefing-contract.md](briefing-contract.md) § Successor handoff).

**After ANY restart (the machine's or cmux's), the FIRST act is `slopweaver fleet resume`, which the desktop types into a tab of its own, never yours** — it resumes every bare-shell seat on its saved session, the chair first on the pin, and relaunches every walled one; run in the chair it would wait on your own `reoriented` line ([reboot.md](reboot.md) § Reoriented). `cmux reseat --all` selects WALLED seats only, so it never brings a restore-off bare tab back; a seat it still refuses `NO_LIVE_SESSION` is a worker's for `slopweaver session re-seat`, the chair's for `cmux reseat <its ref>` once its tab shows a prompt. cmux's own restore is kept off (`fleet restore-policy`) because, left on, it reopens every seat running a bare `claude --resume` with no fd-3 setup token, so each reads `Not logged in · Please run /login` (the chair too) — Claude Code 2.1.289 right-aligns it as `Not logged in · Run /login` on the mode row, or on its own row above the prompt box once the mode row is full, and the wall reader matches all three. A seat whose session booted on no configured plan is walled too, however idle its screen looks — the `claude seat` hook refuses its every prompt. `cmux reseat --all` relaunches each walled seat in place with `--resume` on a routed plan, the chair first, so every seat keeps its context. It ends on the console's state. `session re-seat` then closes and fresh-spawns any walled seat reseat refused `NO_LIVE_SESSION`, one boot at a time under the capacity read, never the pinned chair. Never `/login` in a seat: that writes the shared keychain. A `logged-out` or `limit-retrying` row in step 2 is the same signal on any tick ([stuck-chats.md](stuck-chats.md)).

   else, and re-read `slopweaver listen status --json` for the live grade. **Then `slopweaver talk unread`** — every stretch of the owner's speech on a console call since your cursor, relayed or not: read each for an explicit or IMPLIED steer and rule, register or `intake-mark --turn talk-call:…` it this tick, then `talk unread --mark` ([voice-unread.md](voice-unread.md)). **`tick open` first retires every step whose precondition already holds** (`hand recheck`, reading `hand-recheck`, digest `hand recheck:`: the owner is signed in, the owner is in the channel, [rechecking](../../hand/reference/rechecking.md)), **then fires the bot-turn sign-in cards** (`--only turn-signed-out --fire`, reading `turn-sign-ins`: one top-tier card and note per origin a Slack turn is blocked on, [turn-signed-out.md](../../monitor/reference/turn-signed-out.md)), **then the resync sign-in cards** (`--only resync-signed-out --fire`: one card per origin a scheduled resync stopped at, [resync-signed-out.md](../../monitor/reference/resync-signed-out.md)), **then the stopped recipes** (`--only recipe-stopped --fire`, then `--only recipe-repairing --fire`: one card for the stopped set no seat has and no hold of yours explains, then a taken stop's notice, re-judged every tick so it settles the tick its set clears, [recipe-stopped.md](../../monitor/reference/recipe-stopped.md)), **and seats the open set ITSELF**: no seat holding it, it registers ONE `repair-stopped-recipes-*` row and spawns it on opus the same tick, both acts pre-filled in `tick.json` (digest `stopped recipes:`; a RESOLVED one is read every now and then, never every tick, by `slopweaver incident postmortems` (read-only, exit 3 on none), whose printed register command raises one `postmortem-…` row when its postmortem is worth the owner's seat ([incident](../../incident/SKILL.md) § After it resolves). **Then it fires `profile-unloaded`** (`--only profile-unloaded --fire`): a running session whose profile load failed or never ran posts one quiet card naming which sessions the hold has met and are reloading by themselves ([profile-unloaded.md](../../monitor/reference/profile-unloaded.md)). **Then it fires `steer-at-risk`** (`--only steer-at-risk --fire`, reading `steer-at-risk`): a row the owner EXPLICITLY STEERED — your `handover rule --explicit-steer`, which you record the moment you hear one — that is at risk floats ONE note per row and the owner's live call says it at once, never at the deadline ([steer-at-risk.md](../../monitor/reference/steer-at-risk.md)). **Then it fires `fseventsd-bloated`** (`--only fseventsd-bloated --fire`): fseventsd past 2 GiB puts its restart on the owner's queue, held while a voice call is live ([fseventsd-bloated.md](../../monitor/reference/fseventsd-bloated.md)). **Last, it fires `meeting-prep-due`** (`--only meeting-prep-due --fire`): a page tagged to a meeting inside the hour floats as a note above every other note, and comes back on each tick that finds it gone without the owner's press, unless the owner snoozed it ([meeting-prep-due.md](../../monitor/reference/meeting-prep-due.md)). **It claims a Codex reset on every plan at its pause bar** (`codex reset --at-limit`, reading `codex-reset-at-limit`, then `--only codex-reset-failed --fire`): a failed claim floats one note, a refilled plan says nothing ([codex-routing](../../plans/reference/codex-routing.md)). Every fired note stacks beside the ones already up, cascaded; none replaces another step's. **Then `hand wake`** (`snooze-wake`): each note whose snooze lapsed is raised again, beside any note already up ([snoozing](../../hand/reference/snoozing.md)). **It fires `automation-held-on-you`** (`--only automation-held-on-you --fire`, reading `automation-held`): one card per automation stopped on the owner's own uncleared hold ([automation-held-on-you.md](../../monitor/reference/automation-held-on-you.md)), **then reads `slopweaver queue stopping --json`** (reading `queue-stopping`), whose card is the digest's FIRST line, `queue leader:` — **open your chat update to the owner on it** (the owner's P0); `INCOMPLETE`, `CONSOLE NOT READ` and `NOT READ` are unknowns, never none ([derived-narrative](derived-narrative.md)). **It also reads `slopweaver queue refusals --json`** (reading `queue-refusals`, digest `queue refusals:`): every card a gate WITHHELD from the owner's Queue, by key and the gate's own reason, from the running console. A withheld card never reaches the owner, so **each key is yours to route THIS tick** to a seat that fixes its source record until the gate passes — re-record the draft, fix the row's text — never a card asking the owner. `0 withheld` is the only clean line; `INCOMPLETE`, `CONSOLE NOT READ` and `NOT READ` are unknowns, never a zero ([queue-and-triage](../../../docs/console/queue-and-triage.md)). **Before those, it names every declared automation the store does not hold, or holds on an earlier cadence** (`recipes: N declared automation(s) ABSENT|SUPERSEDED`, then one `recipes absent:`/`recipes superseded:` line each): run `slopweaver automation register-standing` THIS tick. `recipes: none due` is printed only when both lists read empty, so an absent roster never reads as an idle fleet. **It prints what CHANGED since tick n-1 and every obligation still standing, folding the rest behind `tick-<n>/digest.txt`** ([derived-narrative](derived-narrative.md#recording-a-tick)); **the digest then OPENS on `broken:`, `sidebar:` and `seatable:`** — each automation held on a failure with whether its finding can be seated, the `automation freshness` reading, and the first ready rows a spawn can take — **act on those first**; a previous tick's hold leaves a row out by exact handover id only ([derived-narrative](derived-narrative.md#recording-a-tick)).
2. **The event prong** — `ListAgents`, `slopweaver cmux list --json`, `slopweaver session watch`. 3. **`slopweaver session close-done`** — BEFORE any screen read. It closes every spawned workspace whose run finished,
   whose ask was settled or whose doc is terminal AND whose screen is idle, closes the ledger rows whose workspaces are
   already gone, and prints one summary line; that line goes VERBATIM into the briefing's collapsed fold. This is the
   mechanism behind the owner asking for done chats to be closed six times in one day: no supervisor
   remembers it, the tick runs it. A row it reports `held … screen busy` is a finished session still talking — read it,
   never close it by hand. It reaps the bot loop's own ask workers and answer reviewers too, once their turn has ended —
   but **never a reviewer mid-verdict**, whose open review holds the reap off exactly as it holds `turn dispatch
--sweep`'s clock off ([stuck-chats](stuck-chats.md)), and a finished [`fleet resume`](../../fleet/SKILL.md) tab. **The one case the verb cannot reach is a workspace whose pull
   request LANDED while its run never recorded a finish** — nothing marks it done, so it is held forever. Nudge it ONCE
   with `cmux send`; if the next tick still shows no finish, settle its board row on the merged commit (`handover settle
<slug> --as answered --witness <sha>`) and close it, because the landing is the fact and the journal event was only
   its witness. MEASURED: two landed pull requests recorded no finish and stayed open. **The same sweep PARKS every at-rest seat** (a parked session leaves the fleet immediately): a live seat on an open run with no done evidence, whose one Claude Code session (with none in its tree, the one Codex thread its run launched, held by a process in that tree) is the run's writer and reads idle with no background work, gets a `parked` checkpoint — worktree, branch, last screen, the Queue question and every unsent draft — and its workspace closed; its summary counts `parked N at-rest seat(s)` ([parking-a-seat](../../handover/reference/parking-a-seat.md)). A seat it KEEPS with a reason (another session holds the run, an unreadable draft register, an unidentifiable seat) is yours to read this tick; `slopweaver handover park <slug>` is the verb for a seat that is not at rest yet. Every running seat is on the highest priority. The owner's answer reseats a parked row with `cmux spawn <slug>`, which reopens that worktree. **A row carrying the owner's standing-session ruling** (`handover rule --standing-session`) is the exception: close-done keeps its seat, and if it is found parked anyway reconcile reads it READY, so step 13 reseats it on sight ([parking-a-seat](../../handover/reference/parking-a-seat.md#a-standing-session-is-never-parked-and-is-reseated-if-it-is)). A seat stays open only while it is doing work (a Codex pass, a gate, a test, and its OWN pull request's CI wait, rebase, red-CI fix and landing — waiting for CI is part of doing work, and so is landing the PR); there is no exception for accumulated context, and a clock or another branch's CI is NOT work (there should never be a session on here that is not doing work). Close-done keeps a seat whose footer counts a background shell, which is how a landing seat's `github checks --wait` keeps it, and an idle one whose run's own branch has an OPEN pull request on GitHub (a read that fails keeps it too, printed), which is how a seat holding for its lap GO keeps it; a seat waiting on a clock or another branch parks itself with `handover park <slug> --wake-at <iso>|--wake-on-checks <owner/repo#n>` (a checks wake on its own open pull request is refused, and so is a clock wake while its run's own pull request is open or unread), and the tick's `handover wake` reading, right after close-done, reseats due wakes in wake order by a visible `cmux spawn`, at most half the boot window's hold less the boots already in it so your fill behind it is never starved, clearing a park on a settled, shipped or terminal row and finishing a merged pull request's run with nothing left but `handover finish` instead of spending a spawn on either. **That reading is the tick's ONE wake: never run `handover wake` again yourself.** MEASURED: a second wake on the same tick booted a seat that had just re-parked on the green head its own reseat acted on, and the spent boot pushed the spawn backoff over the next reseat. The wakes on the machine share one wake journal, so a re-park on a condition a reseat already acted on is held until a new head, a re-run, a merge, a close or a new instant, and a park another wake is reseating reads `reseat-in-flight`. The one follow-up is a backoff deferral: a `spawn-deferred` row in `handover-wake.json` carries `attemptNonce` and `retryAfterIso`, so run `slopweaver handover wake --retry <attemptNonce>` as a background job; it waits for the backoff and reseats that one park this tick, or exits 4 when the backoff opens past fifteen minutes and the next tick's reading takes it ([parking-a-seat](../../handover/reference/parking-a-seat.md)). About 20 idle seats at 300–700 MB each should be tracked closed and resumable for later, and that capacity used for slopweaver code-quality PRs and work that is not blocked on the owner — so the freed capacity fills with the next ready row that HAS the owner's steer, slopweaver code-quality rows first among equals, **in the same tick as the park**. A park with no fill behind it is the failure the owner keeps walking in on (basically no sessions running except the supervisor, and no capacity maxing): at any moment the owner should see what is being worked on and agree it is the best thing, so the fold names each freed slot's new row, or the ceiling that stopped it.

## Standing traps

Every one below FIRED in a supervisor's own tool results over eleven handoffs — measured, not remembered. The
dead ones were deleted rather than carried ([state-doc.md](state-doc.md) § Rules found DEAD).

- **`handover list` times out on this board.** Use `slopweaver handover reconcile --json` for the board read.
- **Never `cmux send` into the supervisor's own workspace.** Report upward with `SendMessage`.
- **A `cmux send` lands QUEUED behind a running turn**, arriving only when it ends. `--interrupt` only when justified; a WEDGED session ignores it, so close and respawn instead.
- **A spawn's pickup is not delivered until it is submitted.** Read-screen the new workspace; re-send if the prompt sits typed and unsent.
- **`Read` caps at 25k tokens** — `File content (N tokens) exceeds maximum allowed tokens (25000)`. Read a large file by offset, or delegate the read.
- **`slopweaver github read` needs a full https URL** — not `--repo`/`--number`.
- **`slopweaver handover answer` wants `--answer`**, `handover settle` wants `--as filed|answered|declined` (and `--card done|recut|kept` on a relay row over an open hand card), and `handover reconcile --json`'s `unregistered` entries are strings, not objects.
- **The harness stops a background bash at its `timeout`**: 30 minutes by default, 2 hours at most (`timeout: 7200000`). MEASURED: a `automation resync --atlas datadog` backgrounded with `timeout: 7200000` ran 76m30s to success (`resync-state/resync-atlas-datadog.json`); with none, the same walk died at 30 minutes.
- **The merge guard is base-relative** — pass `--base origin/main` or a wrong-tree verdict succeeds quietly.
- **A session announcing "closing now" with an unmerged PR orphans the landing.** Interrupt-deliver, or spawn a landing session.
- **A long grep over a big repo times out.** Bound it, or narrow the path first.
- **A chat reply is not a record.** MEASURED: an answer composed in a supervisor's own chat was
  never carded, and the owner re-asked it of the next supervisor 80 minutes later. The turn the owner typed IS addressable —
  `transcript:<session>#<turn>` — so anchor the row or mark to it THE SAME TICK.
