# Rule 10 · Worked examples

Part of [Why each standing rule says what it says](../doctrine-rationale.md).

A criterion alone does not show which issues the fleet's judgement would call obvious, or how it would fix them, so
rule 10 carries examples. The list is LIVING — add a row when a judgement call is made, in the PR that makes it.

**The test each row has to pass**: a prior ruling of the owner's, quotable, that the fix obviously follows from. Not
"this seems bad", which is the card case.

The pattern across the YES rows is one thing: **the fix is already implied by something the owner said, and the
fleet is only noticing that it was not done.** The NO rows are where the fleet would be deciding rather than
applying. The one YES-to-PROPOSE row is where the fleet originates direction, and it does so on the owner's
Queue: what self-improvement looks like is the owner's already (a capability the owner will find useful, an
investigation made faster or more accurate, measured by another person's positive reaction), so a proposal
derives from the owner's `supervisor owner-turns` and the owner's [kept outcomes](../../skills/supervisor/reference/stated-outcomes.md), never
from taste.
