# 7 · The browser is the FALLBACK, not the first reach

Part of [What an atlas must be](../atlas-intent.md).

The owner's ruling, made alongside §6, narrowing §2 without weakening it — both surfaces stay mandatory to
MAP. The browser is the fallback for ingest where the API cannot answer: **if a better option exists, use
the better option.**

So the browser half keeps its full cataloguing duty and takes a bounded ingest duty: a surface the API can
answer is ingested through the API, and the browser carries only what the API cannot reach at all. An
endpoint the browser found and the API also serves is a corroboration record (§4), never a second fetch
path to maintain.
