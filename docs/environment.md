# The `SLOPWEAVER_*` namespace

Every name in this namespace that the shipped code gives meaning to. Two kinds, and they are listed apart
because confusing them wastes a session: **variables** the program reads from the environment, and
**markers** the program prints to stdout for a caller to grep. Provider credentials (`GITHUB_TOKEN`,
`SLACK_BOT_TOKEN`, `LINEAR_API_KEY`, `NOTION_TOKEN`, `DD_API_KEY`, `CF_API_TOKEN`, …) are **not** in this
namespace and are not read from the environment by preference — see [security/credentials.md](./security/credentials.md) for the
secrets store, which is the credential source.

## Configuration

| Variable                         | What it does                                                                                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SLOPWEAVER_HOME`                | The state home. Defaults to `~/.slopweaver`; every path derives from `src/stateHome.ts` and the `src/stateHome/` areas it composes, and nowhere else                                                                                                                   |
| `SLOPWEAVER_SELF_ROOTS`          | The directories `refresh --self` scans, when no `--self-root` is passed. Deliberately not hard-coded: an absolute home path is a leak class the hygiene gate catches                                                                                                   |
| `SLOPWEAVER_PROGRESS_JSON`       | Opt into the machine-readable progress lane, for a programmatic consumer that parses progress rather than watching it                                                                                                                                                  |
| `SLOPWEAVER_SLACK_STALL_MINUTES` | How long ONE Slack conversation may go with no page, thread reply or flush before the crawl abandons it and moves on. Defaults to 10 minutes; an unparseable, zero or negative value falls back to that, and a window too short for a healthy round-trip is clamped up |

## Break-glass

Each of these lifts one refusal — or, where the table says so, a NAMED few that mean the same thing — and
every one is **named in the refusal that mentions it**: a guardrail whose message does not tell you how to get
past it is a hard block wearing an escape hatch's clothes. They are separate variables rather than one master
switch on purpose: conflating two deliberate one-off decisions would make each escape broader than the case it
was opened for. Where one variable does cover more than a single refusal, the table names every one, so the
blast radius is still read off this page rather than discovered.

| Variable                                       | Lifts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SLOPWEAVER_ALLOW_RAW`                         | The raw-tool block in the admit door and the `PreToolUse` hook                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `SLOPWEAVER_ALLOW_BROWSER_LAUNCH`              | The `PreToolUse` hook's refusal of a raw browser launch — `open` into a browser, a Playwright CLI, a browser binary, `osascript` telling a browser (rule 3). `SLOPWEAVER_ALLOW_RAW` and `SLOPWEAVER_ALLOW_BASH` never open it, and it opens neither. For proving the refusal; the `slopweaver browser` verbs are the browser path                                                                                                                                                                                                     |
| `SLOPWEAVER_ALLOW_POLL`                        | The poll gate's refusal of a second read of the same log, pid or task within 60 seconds, when it changed or cannot be proven unchanged                                                                                                                                                                                                                                                                                                                                                                                                |
| `CLAUDE_CODE_SESSION_ID`                       | Read by `slopweaver hatch open` — a journalled outbound grant names the session it was issued to and is never transferable                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ALLOW_FABLE_OVERRIDE`                         | `cmux spawn --model fable`'s refusal — the owner's name for it, verbatim, so the refusal's re-run line is the one the owner wrote; the register's `fable-worker` row, the one variable there outside the `SLOPWEAVER_ALLOW_` family                                                                                                                                                                                                                                                                                                   |
| `SLOPWEAVER_DOOR_OVERRIDE`                     | A named `warn`-severity door finding, by its own override token                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `SLOPWEAVER_ALLOW_LARGE_FILES`                 | The per-file size ceiling on a `refresh --self` scan                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `SLOPWEAVER_ALLOW_ATLAS_EVIDENCE_LOSS`         | An atlas publish that would empty a kind the store already holds, or a FAILED run publishing less evidence than it has. For a provider that genuinely dropped every row of a kind — `atlas <platform> restore` is the way back from the other cases                                                                                                                                                                                                                                                                                   |
| `SLOPWEAVER_ALLOW_ATLAS_ROW_VOLUME`            | An atlas publish that would store voluminous data as ROWS — a kind the atlas declares shape-indexed carrying entities, or a kind over `UNDECLARED_ROW_CEILING` with no verdict in `kindVolumes` (the owner's ruling; [atlas-intent §6](atlas-intent/06-holdings.md)). For a one-off local capture a session is about to weigh, or a family whose verdict changes in the same change                                                                                                                                                   |
| `SLOPWEAVER_ALLOW_UNROOTED_BRIEF_PATH`         | `handover register`'s and `cmux spawn`'s refusal of a brief naming a file by a path relative to the state home, which a reading seat cannot root ([why](doctrine-rationale/seat-never-scans.md)). For a token that is a PATTERN under discussion rather than a file to open, or the owner's words quoted verbatim                                                                                                                                                                                                                     |
| `SLOPWEAVER_ALLOW_ANCHOR_ATTRIBUTION`          | `handover register`'s refusal of a row whose `--ask` or example scene says someone other than the poster of its Slack `--anchor` asked, tagged or posted it. For a namesake, or a sentence reporting what someone said about the message                                                                                                                                                                                                                                                                                              |
| `SLOPWEAVER_ALLOW_DISK_WIDE_SCAN`              | The seat-side `disk-scan-guard`'s refusal of a `find` or `bfs` rooted at `/` or `$HOME`. For a genuine whole-disk audit, or a scan already bounded by something the gate cannot read such as `-prune` or `-xdev`                                                                                                                                                                                                                                                                                                                      |
| `SLOPWEAVER_ALLOW_UNBOUNDED_SEARCH`            | The same guard's refusal of a `grep` or `rg` inside `$SLOPWEAVER_HOME/corpus`, or a recursive `grep` from `/` or `$HOME`. For a file you know is small that no `store` verb reads, a timed parity check, or diagnosing the corpus files themselves                                                                                                                                                                                                                                                                                    |
| `SLOPWEAVER_ALLOW_WHOLE_TREE_CHECK`            | The seat-side `whole-tree-check-guard`'s refusal of a run that re-proves the whole tree — `yarn lint`/`dev lint` without `--only` or `--lane local`, `--only oxlint`/`named-object-params`/`prettier`/`knip`, `oxlint --type-aware` over a directory, `tsc` over a project, `yarn typecheck`, `yarn build`, a whole `vitest` lane, `prettier` checking anything but files, `knip`. For CI being down, or measuring the lap itself                                                                                                     |
| `SLOPWEAVER_ALLOW_FOREIGN_PR`                  | The authorship check on editing a pull request somebody else opened                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `SLOPWEAVER_ALLOW_PR_REPLACE`                  | The refusal to replace a whole pull-request description wholesale, asked only when the live title or body is not this door's own last confirmed write                                                                                                                                                                                                                                                                                                                                                                                 |
| `SLOPWEAVER_ALLOW_DIRTY_TREE`                  | `github stack adopt`'s refusal to proceed with uncommitted changes                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `SLOPWEAVER_ALLOW_UNCARDED_PAGE`               | `handover settle`'s refusal of a page witness, and `handover finish`'s of a page artifact, when that page never reached the owner's Queue — no question naming it, no ruling, no hand step (measured: nine briefings the owner asked for once closed with no card). For a page nobody reacts to: a regenerated proof page, an internal artifact                                                                                                                                                                                       |
| `SLOPWEAVER_ALLOW_UNREVIEWED`                  | `handover finish`'s refusal while a declared probe still fails, AND `codex status --check`'s Codex-pairing floor (AGENTS.md rule 9) — the one variable covering two refusals, because both mean "this work has not been checked". It is NOT landing authority: `github enqueue` and `github merge --admin` re-ask the floor and never read it                                                                                                                                                                                         |
| `SLOPWEAVER_ALLOW_NO_RUN_GATE`                 | Every gate in the run hook — the kill switch, named in every refusal it can cause (`SLOPWEAVER_NO_RUN_GATE` is read too, never printed)                                                                                                                                                                                                                                                                                                                                                                                               |
| `SLOPWEAVER_ALLOW_MAIN_CHECKOUT_BRANCH_SWITCH` | The main-checkout branch guard. Honoured as an inline prefix on the refused command itself (`VAR=1 git -C … checkout …`), as its refusal prescribes — the hook runs BEFORE the command, so an inline assignment is never in its own environment and it reads the prefix off the command                                                                                                                                                                                                                                               |
| `SLOPWEAVER_ALLOW_MAIN_CHECKOUT_WRITE`         | The main-checkout dirty-write and edit guards (a separate variable from the branch switch, because they are separate deliberate acts)                                                                                                                                                                                                                                                                                                                                                                                                 |
| `SLOPWEAVER_ALLOW_HOME_GIT_IMPLICIT`           | The seat-side `home-git-guard`'s refusal of a remote-facing `git` (fetch, pull, merge, rebase, push, ls-remote, an `origin/…` read) that names no repository and resolves to `$SLOPWEAVER_HOME`'s own state repository. Honoured inline on the refused segment too. For deliberate work on the state repository that cannot spell the home as a literal `-C` path                                                                                                                                                                     |
| `SLOPWEAVER_ALLOW_CALL_STATE_DELETE`           | The seat-side `call-state-guard`'s refusal of a `Bash` command it can read (a tripwire: a nested shell or interpreter passes) that deletes, moves, truncates or overwrites a console-voice call file, the call index, an unread cursor or the call quarantine ledger in a live home — the environment's `$SLOPWEAVER_HOME` and the account default `~/.slopweaver`, both. Honoured inline on the refused segment too. A gone call is accepted with `slopweaver talk quarantine`, never removed; a test points at a throwaway `--home` |
| `SLOPWEAVER_ALLOW_MULTIPLE_SOCKET_CONNECTIONS` | `listen`'s refusal when Slack reports a second Socket Mode connection for this app — with two, a tag reaches only one of them                                                                                                                                                                                                                                                                                                                                                                                                         |

**Some refusals deliberately have NO variable here.** The OUTBOUND escape-hatch rows (`wall`, `voice-rules`,
`bare-refs` and the rest), and the responder whitelist's `responder-allow-open` (which admits every addresser,
the opening that makes prompt injection a real problem — [security/slack-command-boundary.md](./security/slack-command-boundary.md)), take a journalled 30-minute grant instead (`slopweaver hatch open <id> --reason "<why>"`),
never a variable, and the browser
door takes one too — because every variable above is ambient and unbounded: exported once, it holds for the
life of the shell and leaves nobody anything to read afterwards. That is the right trade for a one-off act;
it is the wrong one for a rule whose subject is something that should have stopped.

**Session depth has no variable either:** it is an advisory that warns every session and refuses none
([docs/hooks/session-guards.md](./hooks/session-guards.md) § The session depth advisory), so there is nothing
to waive. Everywhere else the shape holds: one escape per risk, named in the refusal that causes it, and
logged loudly when taken.

## Harness and CI

| Variable                       | What it does                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SLOPWEAVER_COVERAGE_BASE_SHA` | The exact full commit every diff-based lint gate compares this branch against. CI and `github lap` supply it; unset, those gates FAIL and print `SLOPWEAVER_COVERAGE_BASE_SHA=$(git merge-base origin/main HEAD)`. There is deliberately no fallback to `origin/main` inside a gate, because a branch cut before the floor moved compares as a lowering it never made |
| `SLOPWEAVER_ONBOARD_HARNESS`   | Puts `connect` on its fixture path. Must be `1`                                                                                                                                                                                                                                                                                                                       |
| `SLOPWEAVER_CONNECT_FIXTURE`   | Which fixture scenario. Setting it without `SLOPWEAVER_ONBOARD_HARNESS=1` is refused rather than guessed                                                                                                                                                                                                                                                              |

The integration suite reads a further `SLOPWEAVER_RECORD_*` family (`…_SLACK_TOKEN`, `…_GITHUB_TOKEN`,
`…_LINEAR_TEAM` and siblings) when re-recording an outbound cassette. Those are test-harness inputs, not
part of the shipped program, and are documented with the suite that reads them —
[integration-coverage.md](./integration-coverage.md).

## Markers — printed, never read

These are **not** environment variables. They are stable first tokens on a stdout line, so a caller can
recognise a result in a live session's screen text without parsing prose.

| Marker                   | Printed by                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SLOPWEAVER_TURN_READY`  | `turn resume --answer`, when the answer validated against its pinned brief                                                                                                                                                                                                                                    |
| `SLOPWEAVER_TURN_FAILED` | `turn resume --failed` ONLY — the worker's own terminal report. A validate refusal from `turn resume --answer` (malformed JSON, a grounding mismatch, an over-cap body/index, …) prints and stores NO marker at all — it is retryable, not terminal, so the sweep must keep reading the ask as still-working. |

Setting one of these in the environment does nothing at all.
